# FACS 形式化可检验演算系统  
## Formalized Adjudication Calculus System v1.3（整合版）  

### 声明  
本文是一个自举判定系统（self‑bootstrapping adjudication system）。它定义自身的全部术语、操作与边界，不预设任何外部元系统作为仲裁者。本文所使用的一切概念——包括但不限于“状态”“算子”“依赖”“一致性”“锚定”——其指涉定义严格锁定于本文框架内部。任何对上述术语的外延替换均被视为非法置换，不得作为反驳本文的逻辑武器。

## 一、适用范围与排除  

### 1.1 适用范围  
本文适用于一切具备以下特征的形式化命题系统：  
- 命题之间存在可定义的依赖关系；  
- 命题的真值状态可在有限步骤内被定性区分；  
- 系统接受外部注入的新命题，并对其进行内部状态转换。  

凡不具备上述特征的系统——如纯价值判断命题、不可翻译的直觉陈述、不可定位操作路径的猜想——不在本文的讨论范畴之内。  

### 1.2 排除范围  
本文不适用于：  
- 纯主观价值判断（伦理、审美等不可客观翻译的命题）；  
- 孤立个别事实陈述（不具备普适性公理结构）；  
- 人为制度条文（法律、行政规范等拥有独立效力评判体系的文本）。  

将本文判据误用于上述领域，属于范畴误置。

## 二、核心概念界定  

### 2.1 自指涉（Self‑Reference）  
命题内容指向自身，但不构成依赖边。例如：“本系统包含命题 P”是一种合法的自描述。自指涉属于句法结构的合法特征，不构成无效理由。  

### 2.2 循环论证（Circular Dependency）  
依赖图中出现有向环：C ∈ Dep(C) 或 C → … → C。循环论证构成推导结构的非法闭环，被禁止作为可检验域的合法推导路径。  

**二者不可混淆。** 前者是句法层面的自我指向，后者是证明链条的逻辑闭环。  

### 2.3 状态（State）  
L1 内每个命题在同一时刻拥有且仅拥有以下八种基态之一：  

| 标记 | 名称 | 语义 |
|------|------|------|
| ∇ | 探索态 | 仅来自 L2 的暂存，L1 只读引用 |
| ◇ | 待验态 | 默认初始态，尚未经过确认 |
| □ | 临时确认态 | 已通过一致性检查，可被引用，承担被回滚风险 |
| ◆ | 永久锚定态 | 不可撤销的基岩命题，免疫一切回滚与证伪 |
| ○ | 修订锁定态 | 正在被修改，对外部引用挂起 |
| ● | 回滚痕 | 已被撤销的临时确认态，保留历史指纹但不再参与推导 |
| ⊥ | 证伪坟场 | 被成功推导出否定且无法修复的命题，永久冻结 |
| ↻ | 待回提请 | 已被证伪或作废，正在等待回提审查 |

### 2.4 依赖（Dependency）  
命题 C 的依赖集 Dep(C) 是一个有限集合，包含 C 在逻辑上直接依赖的其他命题的标识符。依赖关系构成有向图。若 Dep(C) 中存在不可定位节点（如 ⊥ 或未定义 ID），则该命题在注入阶段即被标记为非法。  

### 2.5 一致性（Consistency）  
在本文框架内，“一致性”指：给定命题的内容与依赖集，不与当前已确认集及永久锚定库产生显性冲突，且其依赖图不构成有向环。一致性是可判定的句法属性，而非语义真值。

## 三、三层垂直隔离架构  

### 3.1 架构总览  
系统采用三层垂直隔离架构，层间通过预定义黑箱通道通信，下层对上层为只读常量。  

| 层级 | 名称 | 核心职能 | 可访问性 |
|------|------|----------|----------|
| L0 | 超验基底 | 输出静态划界规则与永久锚定存储 | 全局只读，不可内省 |
| L1 | 可检验演算域 | 执行确认、修订、证伪、回滚、回提审查等动态逻辑 | 完全可写，受 L0 约束 |
| L2 | 前理论探索区 | 暂存尚未结构化的猜想、似然模型、试探性框架 | 与 L1 隔离，需经评审方可晋升 |

### 3.2 L0：超验基底（静态只读常量）  
基底在系统启动时一次性注入以下五个不可变常量，之后永久静默。  

**Φ（语法生成器）**  
定义 L1 中合法命题的句法范式。自指涉（命题内容指向自身但不构成依赖边）被显式承认为合法句法结构；循环论证（依赖图中出现有向环）被语法层标记为非法。  

**Ξ（依赖拓扑公理）**  
强制 L1 内所有确认命题的依赖关系构成有向无环图（DAG），禁止循环依赖（C ∈ Dep(C) 或 C → … → C）。自指涉命题因不构成依赖边，不受此限。  

**Γ（自扩展元规则）**  
规定：当 L1 中某确认命题引入新的原子谓词时，该谓词自动获得 Φ 中的合法项资格。扩展在确认瞬间原子生效。  

**Ψ（黑箱裁判接口）**  
L1 向 L0 发起查询的唯一通道，支持以下同步调用：  
- `Ψ.Consistency(prop, dep_set)` → 返回是否与当前锚定库及已确认集无显性冲突（含循环依赖检测）  
- `Ψ.Finalize(prop)` → 请求将某确认态命题晋升为永久锚定，返回接受或拒绝  
- `Ψ.Classify(term)` → 查询某新术语是否符合 Φ 及 Γ 的扩展规则  
- `Ψ.RetractionHistory(prop)` → 查询某命题的撤销历史记录（含归因追溯日志）  
- `Ψ.ValidateNewPrediction(prop, new_pred)` → 验证新预言是否与旧预言构成逻辑独立关系  

### 3.3 L2：前理论探索区（研究态）  
L2 存放尚未获得结构化公理体系的原始猜想。该层不享有任何形式的本体论承诺。  

- 唯一状态：`∇P`（探索态）  
- 操作限制：`∇P` 不可被 L1 的任一算子直接操作  
- 晋升通道（L2 → L1）：需向基底提交 `Ψ.StructuralReview(P)`，审查三项：  
  1. 核心断言是否具备 Φ 下的合法句法表达（含自指涉/循环论证区分检查）  
  2. 是否提供静态的适用域划定  
  3. 是否指明一条在有限资源内可执行的操作路径  
- 审查通过后，`∇P` 转为 `◇P`（待验态），进入 L1。审查驳回后，`∇P` 保留在 L2，可修订后重新提交。

## 四、L1 核心操作算子（动态语义）  

### 4.1 确认算子 `□`  
**前置条件：**  
- 当前状态为 `◇C`  
- 依赖集 `Dep(C)` 无环  
- `Ψ.Consistency` 返回 True  

**转换：** `◇C → □C`  

**副作用：**  
- 若引入新谓词，触发 Γ 扩展 Φ  
- 更新 DAG  

### 4.2 永久锚定算子 `◆`  
**前置条件：**  
- 当前为 `□C`  
- `Dep(C)` 全部由 `◆` 或初始基底公设构成  
- `Ψ.Finalize` 返回 Accept  

**转换：** `□C → ◆C`，从动态 DAG 中物理脱离，拷贝入 L0 只读锚定库  

**副作用：** 回滚链条在 `◆C` 处强制中断  

### 4.3 修订锁定算子 `○`  
**前置条件：**  
- 当前为 `□C` 或 `◇C`，且未被锁定  

**转换：** 进入 `○C`（锁定），外部引用挂起。修订完成后提交新版本 `C'` 或解锁恢复  

**修订约束：**  
- 若修订引入的替换推论与原命题核心断言矛盾 → 取消资格，转为 `⊥C`  
- 若修订导致方向性丧失或操作路径无限扩展 → 同样取消资格  

### 4.4 级联回滚算子 `●`  
**前置条件：** 当前为 `□C`  

**转换：** `□C → ●C`；递归闭包 `Revoke(C)`；遇到 `◆` 抛出 `AnchorGuard` 中断  

**副作用：** 从 DAG 移除被撤销节点的边  

### 4.5 自我证伪算子 `¬◇`  
**前置条件：**  
- 从 `{□C, ◆C}` 出发，有限步内演绎出 `C → ⊥`  
- 推导不得引用基底语法规则  

**转换：**  
- `◇C → ⊥C`  
- `□C`：先强制 `●C` 回滚，再转为 `⊥C`  
- `◆C`：静默拒绝（ImmutabilityViolation）  

**可恢复性：** `⊥C` 不可逆转。如需重新提出，须以新条款 `C*` 提交。仅当满足回提条件时，可申请将 `⊥C` 转为 `↻C`。  

### 4.6 回提审查算子 `↻`  
**前置条件：** 当前状态为 `⊥C` 或 `●C`  

**审查三项（逐项硬性检查）：**  
1. **逻辑自查与错误排除：** 提出方须提交自查报告，定位并承认先前导致撤销的具体错误（逻辑错误/数据误解/执行偏差），且该归因须可追溯至 `Ψ.RetractionHistory`  
2. **新独立预言供给：** 提出方须提供一项新的、与旧预言逻辑上独立的、可证伪的预言，满足可定量/可操作/方向性三项条件，且经 `Ψ.ValidateNewPrediction` 确认与旧预言非等价关系  
3. **误判归因可追溯：** 撤销裁决的归因必须可追溯至具体的错误，而非时间流逝、观测波动或“再看一次”的重复请求  

**转换：**  
- 三项全通过 → `↻C → ◇C`（重新进入待验态，初始依赖集清空，须重新确认）  
- 任一失败 → `↻C → ⊥C`（永久冻结，该命题 ID 作废）  

**禁止情形（自动驳回）：**  
- 仅以观测条件变化、边界条件重新审视、重新表述旧预言为由申请  
- 新预言与旧预言逻辑上不构成独立关系  

### 4.7 自指涉与循环论证的运行时检查  
任何新条款注入时，`Ψ.Consistency` 执行：  
- 自指涉检查：命题内容指向自身是否构成依赖边？若否，允许  
- 循环论证检查：依赖图中是否存在 `C ∈ Dep(C)` 或 `C → … → C` 的有向环？若是，直接驳回并标记 `⊥_Syn[CIRCULAR_DEP]`

## 五、累积保护定理（核心不变量）  

1. **基底不可侵性：** L1 任何算子不得修改 L0 常量  
2. **锚定不可逆性：** `◆C` 免疫一切回滚与证伪  
3. **历史不可撤销性：** `●`、`⊥`、`↻` 状态永久记录于历史日志，不可擦除  
4. **回提不可零成本递归：** 每次回提必须满足三项条件（自查排错+新独立预言+归因追溯），否则永久冻结

## 六、系统启动序列（基底一次注入）  

启动时，基底向 L1 注入三条初始公设，直接标记为 `◆`：  

- **K0：** 排中律在 L1 内有效  
- **K1：** 矛盾律是 L1 内唯一绝对禁止条件  
- **K2：** L1 内任何证明链条长度 ≤ 硬件锚定的极大有限常数

## 七、FACS 模拟引擎（FACS‑SE）  

### 7.1 定位与范围  
FACS‑SE 是 L1 动态层的离线测试环境，用于在固定基底常量下批量注入随机命题，观测系统长期行为。  

### 7.2 模拟运行机制  
每步循环执行以下阶段：  

**（1）注入阶段**  
- 若当前条款数未达容量上限，生成新命题并随机生成依赖集  
- 执行 `Ψ.Consistency` 检查：  
  - 若依赖集中存在有向环 → 标记 `⊥_Syn[CIRCULAR_DEP]`，丢弃  
  - 若命题内容指向自身但不构成依赖边 → 合法，允许注入  
  - 若依赖集包含不可定位节点 → 标记 `⊥_Syn[DEP_INVALID]`，丢弃  
  - 否则注入为 `◇C`  

**（2）确认阶段**  
- 遍历所有 `◇C`，按判定条件执行 `□C`  
- 若 `Ψ.Consistency` 返回 False → 直接转为 `⊥C`  

**（3）锚定阶段**  
- 遍历所有 `□C`，按判定条件申请 `◆C`  
- 调用 `Ψ.Finalize(C)`，检查依赖纯血性（Dep 全部为 `◆`）  
- 若通过 → `□C → ◆C`（从 DAG 脱离）  
- 若失败 → 维持 `□C`  

**（4）证伪阶段（`¬◇`）**  
- 按判定条件选择 `□C` 或 `◇C` 尝试构造否定演绎  
- 若从 `{□,◆}` 中推出 `C→⊥`：  
  - 若为 `◇C` → `⊥C`  
  - 若为 `□C` → 先强制 `●C`（回滚闭包，遇 `◆` 中断），再转 `⊥C`  
  - 若为 `◆C` → 静默拒绝（ImmutabilityViolation）  
- 证伪成功后，按判定条件将 `⊥C` 转为 `↻C`，否则永久冻结  

**（5）回滚阶段（`●`）**  
- 按判定条件选择 `□C` 执行回滚  
- 计算 `Revoke(C)` 闭包，遇 `◆` 抛出 `AnchorGuard` 中断  
- 命中节点全部转为 `◇`（若为 `□`）或维持 `●`  
- 回滚后，按判定条件将 `●C` 转为 `↻C`  

**（6）回提审查阶段（`↻`）**  
- 遍历所有 `↻C`，执行三项审查（自查排错+新独立预言+归因追溯）  
- 若三条件全通过 → `↻C → ◇C`（重新进入待验，Dep 清空，须重新确认）  
- 若任一失败 → `↻C → ⊥C`（永久冻结，ID 作废）  
- 自动驳回：仅以观测条件变化、边界条件重新审视为由申请；新预言与旧预言等价  

**（7）修订阶段（`○`）**  
- 按判定条件选取 `□C` 或 `◇C`，进入 `○C` 锁定，外部引用挂起  
- 若修订引入的替换推论与原命题核心断言矛盾 → 取消资格，转为 `⊥C`  
- 若修订导致方向性丧失或操作路径无限扩展 → 同样取消资格  
- 若修订合法，解锁恢复为 `◇C'`（新版本），Dep 清空  

### 7.3 状态转移图  
```

[注入] → ◇C ──┤→ □C (confirm) ──→ ◆C (anchor, 依赖纯血)
│      │                    │
│      ├──● (revoke)────────┘ (遇 ◆ 中断)
│      │
│      ├──¬◇ (falsify)─────→ ⊥C
│      │                         │
│      └──○ (revise)────────────→ ◇C' 
│
└──⊥_Syn (循环/语法排斥) → 丢弃

⊥C/●C ──→ (retry) ──→ ↻C (待回提请)
│
┌───────────────┼───────────────┐
│               │               │
条件1           条件2           条件3
(自查排错)      (新预言)       (归因追溯)
│               │               │
└───────────────┼───────────────┘
│
┌─────────┴─────────┐
三全通过             任一失败
│                   │
▼                   ▼
◇C                 ⊥C(永久)
(重新确认，Dep清空)      (ID作废)

```

### 7.4 输出统计指标  
每步记录以下指标：  
- anchored：`◆` 数量  
- confirmed：`□` 数量  
- pending：`◇` 数量  
- revoked：`●` 数量  
- falsified：`⊥` 数量  
- revising：`○` 数量  
- retry_pending：`↻` 数量  
- total_active：`□+◇+◆+○`（非死亡活跃）  
- max_depth：DAG 最大深度  
- avg_deps：平均依赖数  
- entropy：基于活跃状态比例的香农熵（base=2）  
- retry_success_count：回提审查通过次数  
- retry_fail_count：回提审查失败次数  
- circular_blocks：循环论证拦截次数

## 八、全域核验刚性执行协议（对撞裁决）  

本协议专门针对**任意一对互逆命题系统** `P` 与 `¬P`，执行完整的、不可上诉的句法一致性裁决。它利用前述 L0‑L1 机制，在 L1 层内完成从准入到最终裁决的全流程。  

### 8.1 基础公理  
本协议锚定 L0 常量 `(Φ, Ξ, Γ, Ψ)` 及初始公设 `K0‑K2`。博弈论规则 M 已部分锚定为 L0 宪法。  

---

### 第一阶段：L2 准入与句法审查  

**目标：** 建立命题的存在权，确保其具备进入演算域的资格。  

**Step 1.1: 命题注入**  
- **操作对象：** 原始命题系统 `P` 及待检验的逆命题系统 `¬P`。  
- **动作：**  
  - 将 `P` 和 `¬P` 的全部公理、推理规则、静态定义域声明，作为独立的命题束存入 L2 前理论探索区。  
  - 两者初始状态均为探索态 `∇`。  

**Step 1.2: 结构性审查（Ψ.StructuralReview）**  
- **触发：** 提交晋升 L1 申请。  
- **检查项：**  
  1. **句法合法性（Φ）：** 扫描 `P` 和 `¬P` 的全部内容。必须符合 Φ 定义的 BNF 语法。自动甄别并拦截 `⊥_Syn[CIRCULAR_DEP]`（循环论证）。  
  2. **静态定义域（见 §1.1‑§1.2）：** 检查 `P` 和 `¬P` 是否已用不可滑移的术语锁定其适用域。术语指涉必须满足语义自足性（本文声明）。  
  3. **操作路径可定位性：** 确认 `P` 和 `¬P` 的核心断言，是否指明了在有限资源内可执行的定性区分路径。  
- **裁决逻辑：**  
  - 通过：`∇(P) → ◇(P)`，`∇(¬P) → ◇(¬P)`。两者进入 L1 待验态。  
  - 驳回：保留在 L2。修订后可重新提交。  

---

### 第二阶段：独立确认与内部一致性检验  

**目标：** 检验 `P` 和 `¬P` 作为独立系统，是否自洽。  

**Step 2.1: 依赖拓扑构建**  
- **操作：** 为 `◇(P)` 和 `◇(¬P)` 分别解析其内部公理间的依赖关系，构建依赖图 `DAG_P` 和 `DAG_¬P`。  
- **检查：** Ψ.Consistency 巡检 Ξ 公理，确保两张图均无有向环。  
- **存档：** 两者的初始 DAG 拓扑被 Ψ.RetractionHistory 永久存档。  

**Step 2.2: 独立一致性推演**  
- **操作：** 在 L1 中开启两个独立的、资源对称的沙箱。  
  - **沙箱 A（原体系推演）：** 对 `◇(P)` 执行确认 `□`。成功后，在 `K2` 步内穷举展开全部句法后承，实时扫描 `A ∧ ¬A` 矛盾。  
  - **沙箱 B（逆体系推演）：** 对 `◇(¬P)` 执行确认 `□`。成功后，在 `K2` 步内执行同样的穷举展开与矛盾扫描。  
- **裁决逻辑（完全对称）：**  
  - 无矛盾：`◇(P) → □(P)`；`◇(¬P) → □(¬P)`。  
  - 检出矛盾：触发自我证伪 `¬◇`。该命题系统状态迁移至 `⊥`。流程对该系统终止。  
- **状态：**  
  - 若 `P` 和 `¬P` 均为 `□`，则进入第三阶段。  
  - 若任一方为 `⊥`，则核验终止。结论：失败的系统不具备参与合并对撞的资格。  

---

### 第三阶段：关联性对撞与矛盾诊断  

**目标：** 裁决两个自洽系统 `P` 和 `¬P` 在逻辑上能否共存。  

**Step 3.1: 临时合并推演**  
- **操作：**  
  - 构建临时合并依赖图 `DAG_merged = DAG_P ∪ DAG_¬P`。  
  - 将 `□(P)` 和 `□(¬P)` 的所有公理注入此合并域。  
  - 启动 `K2` 步穷举推演，应用所有推理规则。  
- **监控：** Ψ.Consistency 守护进程实时扫描整个句法后承空间，寻找 `A ∧ ¬A` 形式的命题对。  

**Step 3.2: 终局裁决**  

**情况 A – 判定为逻辑矛盾**  
- **触发条件：** 在 `K2` 步内，扫描程序成功捕获一对矛盾命题。  
- **刚性裁决：**  
  1. **事实记录：** FACS 生成一份不可篡改的句法事件报告：“在 `K2` 步内，系统 `P` 和 `¬P` 的合取直接/间接导出矛盾。两者被证明为互斥，无法在 L1 共存。”  
  2. **系统锁定：** 强制触发修订锁定算子 `○`。  
     - `□(P) → ○(P)`  
     - `□(¬P) → ○(¬P)`  
  3. **解释：** FACS 不作出“P 错”或“¬P 错”的裁决。它只陈述一个客观句法事实：“`P` 和 `¬P` 的并集是不一致的。”这终结了关于两者兼容性的所有争论。  
  4. **出口：** 流程暂停。`P` 和 `¬P` 的支持者必须分别在各自被锁定的副本上进行修订，产生新版本 `P'` 和 `¬P'`。任何新版本必须从第一阶段重新开始核验。  

**情况 B – 判定为逻辑正交**  
- **触发条件：** `K2` 步推演全部完成，Ψ.Consistency 未返回任何矛盾。  
- **刚性裁决：**  
  1. **事实记录：** FACS 生成报告：“在 `K2` 步内，系统 `P` 和 `¬P` 的合取未导出矛盾。两者被判定为逻辑正交关系。”  
  2. **解除锁定，恢复状态：**  
     - `○(P)` 解除，恢复为 `□(P)`  
     - `○(¬P)` 解除，恢复为 `□(¬P)`  
  3. **解释：** FACS 裁决 `P` 和 `¬P` 是两个互不干涉、独立自洽的形式体系。它们可以在 FACS 内同时拥有“临时确认”的合法地位，如同非欧几何与欧氏几何。  
  4. **出口：** 流程结束。两者均获得在 L1 中继续演化、独立接受未来检验的资格。  

---

### 第四阶段：后决程序与长效准则  

**目标：** 将裁决结果固化为系统记忆，并规范未来的挑战。  

**Step 4.1: 元数据锚定**  
- **操作：**  
  - 第三阶段的裁决报告、`DAG_merged` 快照、矛盾/正交的具体证明路径，被打包为一个元命题束 `META_PvN`。  
  - 申请 `Ψ.Finalize(META_PvN)`。  
- **结果：** 若通过，`META_PvN` 获得 `◆` 态，成为 L0 只读锚定库的一部分。这意味着“`P` 和 `¬P` 在此版本下是矛盾/正交关系”成为一条不可更改的历史铁则。  

**Step 4.2: 版本迭代的刚性准入**  
- **规则：** 任何对 `P` 或 `¬P` 公理内容的修改（增、删、改术语），都将导致其身份 ID 变更。  
- **后果：** 新版本 `P'` 或 `¬P'` 被视为一个全新的、从未被检验过的理论。它必须从第一阶段重新开始，走完整套核验流程。任何试图引用旧版本 `META_PvN` 裁决来为新版本辩护的行为，都将被 Ψ.Consistency 识别为定义域滑移或循环论证而直接驳回。

## 九、操作命令集  

系统接受以下操作指令：  

- **注入 L2 <命题>** → 放入研究层  
- **晋升 <命题>** → L2→L1 存在层申请  
- **确认 <命题>** → `◇C → □C`  
- **锚定 <命题>** → `□C → ◆C`  
- **证伪 <命题>** → `¬◇C`  
- **回提 <命题> [自查报告] [新预言]** → 提交 `↻C` 审查  
- **修订 <命题>** → 进入 `○C` 锁定  
- **状态** → 显示当前所有条款及 DAG  
- **历史 <命题>** → 查询撤销归因日志  
- **对撞 <P> <¬P>** → 启动第八章的全域核验刚性执行协议

## 十、闭合规则  

本文所指涉的全部内容，在其内部要么构成对系统的**补充**（可兼容扩展），要么构成对系统的**可定位反驳**，要么**彻底推翻本系统以及彻底对其指涉定义取反**。  

本文不追求完备性。本文通过划界保证一致性。本文的一致性不由内部证明，而由刚性构造保证：L0 常量不可修改、DAG 无环、矛盾律为绝对禁区、证明链有硬件锚定的上限。任何试图在系统内部质疑 L0 的操作，在架构层面即不可能；任何试图局部修正 L0 的尝试，只能通过整体推翻系统并重启来实现。
